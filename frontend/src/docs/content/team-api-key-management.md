# 团队 API Key 管理

企业团队不要把一个 API Key 发给所有人。更稳的方式是按团队、项目、工具或预算拆 Key。

## 推荐拆分方式

| 拆分维度 | 示例 | 好处 |
| --- | --- | --- |
| 按工具 | Claude Code Key、Codex Key | 快速判断协议和客户端问题。 |
| 按项目 | 官网项目 Key、内部工具 Key | 成本和问题归因更清楚。 |
| 按人员 | 开发 A Key、开发 B Key | 适合小团队试用期。 |
| 按预算 | 测试 Key、生产 Key | 避免测试消耗影响正式项目。 |

## 管理原则

- Key 只发给需要的人。
- 不在群聊里发送完整 Key。
- 离职、项目结束或泄露时及时删除旧 Key。
- 每个 Key 绑定合适分组，避免 Claude Code、Codex、第三方客户端混用。
- 定期查看使用记录和异常错误。

## 排查收益

当请求失败时，独立 Key 可以快速判断：

- 是某个项目配置错了，还是全局链路异常。
- 是 Claude Code 分组问题，还是 Codex 分组问题。
- 是某个人本地环境问题，还是平台或上游问题。
