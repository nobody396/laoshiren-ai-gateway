# 多模型统一接入管理指南

企业使用 AI 工具时，通常不会只用一个模型。研发可能用 Claude Code，产品可能用 ChatGPT，部分场景还会用 Gemini、图像模型或 OpenAI 兼容客户端。多模型统一接入的目标，是让这些工具在管理上归到同一套规则里。

## 为什么要统一管理

- 降低每个成员单独配置的成本。
- 避免 API Key 到处复制。
- 统一查看用量和成本。
- 统一处理模型不可用、限流、网络失败等问题。
- 方便企业采购、财务和负责人复盘投入产出。

## 应该统一哪些东西

| 项目 | 说明 |
| --- | --- |
| 入口 | 尽量使用统一 API 域名和协议适配。 |
| 密钥 | 按项目、成员、环境拆分 API Key。 |
| 模型 | 明确每个分组可用模型和使用边界。 |
| 费用 | 记录调用、倍率、余额和成本来源。 |
| 权限 | 避免所有人共用一个无限制 Key。 |
| 排错 | 统一处理 401、403、429、502、503。 |

## 老实人AI的使用方式

老实人AI提供统一 API 入口和后台管理能力。你可以为不同项目创建不同 Key，也可以通过分组控制可用模型、倍率和限制。

个人开发者可以先从一个 Key 开始。企业团队建议一开始就按项目拆分，避免后期成本无法归因。

## 推荐分组方式

- 按成员：适合小团队试用。
- 按项目：适合多个产品线或客户项目。
- 按环境：适合区分测试、生产、自动化脚本。
- 按工具：适合分别统计 Claude Code、Codex、SDK 调用。

## 验收标准

一次多模型统一接入算跑通，至少要满足：

- 每个核心工具都能正常调用。
- 后台能看到调用记录。
- 错误能定位到具体 Key、模型或分组。
- 项目负责人能看懂费用归属。
- 团队成员知道遇到问题先查哪篇文档。
