## 2. 先纠正一个旧结论

`docs/ops/SUB2API_UPSTREAM_V0.1.172.md` 第 6 节曾写“本地已有独立且大量定制的 Grok 子系统”。该判断不正确。

截至本清单基线，本地正式代码只有 `anthropic`、`openai`、`gemini`、`antigravity`、`gpt-image` 五类原生平台；生产月卡探针里把 Grok 当作 Anthropic/OpenAI 兼容模型调用，不等于原生 xAI/Grok 平台。以下能力均不存在于 `origin/main`：`PlatformGrok`、Grok OAuth、xAI API Key 账号类型、Grok 专用调度与配额、Grok 媒体路由、Grok 管理端建号。

因此，**原生 Grok 是真实缺口，不是重复功能**。

## 4. 已吸收，不应重复移植

以下 v0.1.172 相关问题已在此前本地 PR 中按本地架构解决：

1. 上游 URL path 注入护栏。
2. OAuth 邮箱所有权接管漏洞。
3. 金额 `NUMERIC(20,8)` 量化。
4. usage 队列满时 fail-closed，避免成功请求漏计费。
5. 每日额度午夜刷新。
6. Anthropic 流中断的部分 usage 计费。
7. 返佣只按实际收款结算。
8. cache/image 计费修复。
9. 上游 TCP/DNS 显式超时。
10. ops 日志退避，避免数据库故障放大。
11. SSE 容量降载与 failover 修复。
12. WebSocket 每轮模型计费与归属。
13. 月卡耗尽从误导性 429 改为明确、不可重试的 403。

## 5. 本轮已批准的 Grok 验收范围

本分支不是只加一个平台下拉框，完成必须同时满足：

1. **建号**：OAuth、SSO 批量导入、xAI API Key、官方/区域/第三方 Base URL、自定义请求头。
2. **文本协议**：Responses、Chat Completions、Messages、Codex 兼容路由、WebSocket、Compact。
3. **模型**：Grok Build、Grok 4.x/4.5、Composer、图像和视频模型，支持账号级模型映射和同步。
4. **配额与调度**：OAuth 刷新、Free/付费识别、配额探测、冷却、连接测试、健康监控、failover。
5. **媒体**：图片生成/编辑、视频生成/编辑/延长/状态/内容代理、媒体资格隔离、分组级启停闸门。
6. **计费**：文本 usage、提示词缓存、图片按次及独立倍率、视频按秒/分辨率及独立倍率；不得绕过本地金额精度和月卡记账。
7. **管理端**：创建/编辑/批量导入、配额显示、模型映射、端点快捷项、Free 徽标和平台图标。
8. **兼容客户端**：Codex、Claude Messages、OpenCode、CC Switch 导入的 Grok 配置。
